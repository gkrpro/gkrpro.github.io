Key Frameworks & Documentation

I've built or contributed to:

Three-Archetype Cloud Governance Model

Foundation of everything. Segments cloud environment into operationally distinct archetypes (Private, Online-Connected, Online-Disconnected). Each has specific controls, stakeholder governance, and implementation patterns.

Multi-Cloud Control Mapping (SCF)

Maps Security Cloud Framework controls across Azure, AWS, and GCP. Includes implementation guidance, service equivalence matrices, and technical configuration details. Makes cloud-agnostic governance practical.

Risk-to-Traceability-to-Acceptability Decision Logic

Framework for making security decisions defensible. Maps risk identification → control compensation → stakeholder acceptability. Includes stakeholder translation matrix (how to explain the same decision to different audiences).

Technology Immaturity Threshold Model

Structured approach to blocking immature technologies (like AI) from cloud deployment. Based on: defined threat models, mature controls, team capability, and measurement criteria. One "no" on any dimension blocks deployment.

1600+ AI-related risks categorized by cause and domain. Used to inform threat models, assess control maturity, and guide secure deployment of AI/ML in cloud environments.

How I Think About Security

Security should be pragmatic, not theoretical

Pure security is a luxury no organization can afford. My frameworks are built for the real world: competing priorities, resource constraints, and business urgency. The goal isn't perfect security. It's defensible security that enables business.

Credibility comes from traceability, not politics

I avoid political maneuvering. Instead, I build frameworks that make my reasoning visible: risk assessments, control mappings, decision records, stakeholder translation. When people understand your logic, they trust your judgment.

Cloud security is not cloud-native by default

Cloud-agnostic governance is harder than it looks. I think operationally across Azure, AWS, and GCP. Same security function, different implementation per provider. Service equivalence matters. Platform knowledge matters.

Invisible work doesn't build credibility

The work you do to align stakeholders, design frameworks, and make judgment calls is invisible to decision-makers. I systematically document it: decision records, framework evolution, stakeholder alignment sessions. Visibility builds organizational credibility.
